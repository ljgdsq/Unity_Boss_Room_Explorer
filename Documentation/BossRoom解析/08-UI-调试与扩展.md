## 1. UI 的组织方式

Boss Room 的 UI **不是 MVVM 框架**，而是三个简单原则：

1. **每个 Panel 是一个 MonoBehaviour**，`[Inject]` 拿依赖；
2. **Mediator 负责"面板之间的协调"**，例如 `LobbyUIMediator` 协调"加入/创建"两个子面板；
3. **数据变化通过事件/消息驱动**，UI 不轮询。

```
UI/
├── Lobby/            LobbyUIMediator、LobbyJoiningUI、LobbyCreationUI、LobbyListItemUI
├── CharSelect/       UICharSelectPlayerSeat、UICharSelectClassInfoBox、CharacterSwap 预览
├── HUD/              PartyHUD、HeroActionBar、UIHealth、UIName
├── 通用              PopupManager/PopupPanel、UIMessageFeed、UISettingsPanel、UITooltipDetector
└── 连接状态          ConnectionStatusMessageUIManager、IPUIMediator、IPConnectionWindow
```

### 1.1 依赖注入示例

```csharp
// Gameplay/UI/Lobby/LobbyUIMediator.cs:36
[Inject]
void InjectDependenciesAndInitialize(
    AuthenticationServiceFacade authenticationServiceFacade,
    LobbyServiceFacade lobbyServiceFacade,
    LocalLobbyUser localUser,
    LocalLobby localLobby,
    NameGenerationData nameGenerationData,
    ISubscriber<ConnectStatus> connectStatusSub,
    ConnectionManager connectionManager)
{
    ...
    m_ConnectStatusSubscriber.Subscribe(OnConnectStatus);
}
```

好处：
- 不需要 `FindObjectOfType<ConnectionManager>()`；
- 单元测试可以注入 mock；
- 编译期就能发现"依赖不存在"（容器构建时报错，而不是运行时 NPE）。

### 1.2 Mediator 模式

`LobbyUIMediator` 持有 `LobbyJoiningUI` 和 `LobbyCreationUI`，对外暴露：

```csharp
public async void CreateLobbyRequest(string lobbyName, bool isPrivate)
public async void JoinLobbyWithCodeRequest(string lobbyCode)
public async void JoinLobbyRequest(LocalLobby lobby)
public async void QuickJoinRequest()
public void ToggleJoinLobbyUI() / ToggleCreateLobbyUI()
```

子面板只负责"显示/收集输入"，**业务调用集中在 Mediator**。这样"点按钮"的流程只有一处，方便加 loading/错误处理。

### 1.3 `ConnectStatus` 驱动的 UI 状态

每个 UI 都可能关心连接状态：

```csharp
// LobbyUIMediator.cs:59
void OnConnectStatus(ConnectStatus status)
{
    if (status is ConnectStatus.GenericDisconnect or ConnectStatus.StartClientFailed)
        UnblockUIAfterLoadingIsComplete();
}
```

`ConnectionStatusMessageUIManager` 则把状态映射成弹窗文案（见 [02](02-连接流程与状态机.md) 第 7 节）。

## 2. 游戏内 HUD

### 2.1 头顶血条 / 名字：`UIStateDisplayHandler`

文件：`Gameplay/UI/UIStateDisplayHandler.cs`

它挂在 `PlayerAvatar` 上，客户端在 `OnNetworkSpawn` 里做：

```csharp
// 找到主相机与 GameCanvas
var cameraGameObject = GameObject.FindWithTag("MainCamera");
var canvasGameObject = GameObject.FindWithTag("GameCanvas");

if (TryGetComponent(out m_ClientPlayerAvatarNetworkAnimator) && TryGetComponent(out m_NetworkAvatarGuidState))
{
    m_BaseHP = m_NetworkAvatarGuidState.RegisteredAvatar.CharacterClass.BaseHP;
    m_TransformToTrack = m_ClientPlayerAvatarNetworkAnimator.Animator.transform;   // 跟随模型，而不是根节点
}

m_NetworkHealthState.HitPointsReplenished += DisplayUIHealth;
m_NetworkHealthState.HitPointsDepleted    += RemoveUIHealth;
```

**关键点**：
- 血条是**世界坐标 → 屏幕坐标**转换后放在 Canvas 上的（不是 world-space Canvas），在 `LateUpdate` 里更新，保证相机位置已经是本帧最终值；
- 只在客户端执行（`if (!IsClient) enabled = false`）；
- 每个角色 `Instantiate` 一个 `UIState`，`OnDestroy` 时销毁；`DisplayHealth` 内部把 `NetworkVariable<int>` 绑到 Slider。

### 2.2 队伍面板：`PartyHUD`

订阅自己角色上的 `NetworkVariable`（`HitPoints`、`IsGodMode`、`TargetId`）的 `OnValueChanged`，以及队友列表，把每个玩家的状态画成头像 + 血条。
它是"UI 直接消费 NetworkVariable 变化"的典型示例，而不是每帧轮询。

### 2.3 技能栏：`HeroActionBar`

读取 `CharacterClass`（ScriptableObject）里的技能配置，生成按钮；点击时调用：

```csharp
m_InputSender.RequestAction(m_ButtonInfo[buttonType].CurAction.ActionID, SkillTriggerStyle.UI);
```

注意 `SkillTriggerStyle.UI` / `UIRelease`：技能触发方式被抽象成枚举，UI、键盘、鼠标点击走**同一个** `RequestAction` 入口。

## 3. 消息流 UI：`UIMessageFeed`

文件：`Gameplay/UI/UIMessageFeed.cs`

```csharp
[Inject]
void InjectDependencies(
    ISubscriber<DoorStateChangedEventMessage> doorStateChangedSubscriber,
    ISubscriber<ConnectionEventMessage> connectionEventSubscriber,
    ISubscriber<LifeStateChangedEventMessage> lifeStateChangedEventSubscriber)
{
    m_Subscriptions = new DisposableGroup();
    m_Subscriptions.Add(doorStateChangedSubscriber.Subscribe(OnDoorStateChangedEvent));
    m_Subscriptions.Add(connectionEventSubscriber.Subscribe(OnConnectionEvent));
    m_Subscriptions.Add(lifeStateChangedEventSubscriber.Subscribe(OnLifeStateChangedEvent));
}
```

它把"xxx 加入了""Boss 被击败了""门开了"统一显示成一行行消息。

**这就是消息总线的价值**：`UIMessageFeed` 完全不知道 `ConnectionManager`、`ServerBossRoomState` 的存在，只订阅自己关心的消息。

`DisposableGroup` 保证 `OnDestroy` 时统一退订：

```csharp
void OnDestroy() => m_Subscriptions?.Dispose();
```

## 4. 弹窗与加载屏

| 组件 | 作用 |
| --- | --- |
| `PopupManager` | 单例，`ShowPopupPanel(title, content, closeableByUser)`，自动堆叠/关闭 |
| `PopupPanel` | 单个弹窗，支持"重连中 1/2"这种动态文案（`SetupPopupPanel`） |
| `ClientLoadingScreen` / `LoadingProgressManager` | 场景加载进度条，由 `SceneLoaderWrapper` 驱动 |
| `UISettingsPanel` | 画质/音量（URP Volume + AudioMixer） |

加载屏的进度来源不是 `AsyncOperation.progress`（网络场景没有这个），而是 `SceneLoaderWrapper` 的 `OnSceneEvent` 里维护的"每个客户端的加载状态"。

## 5. 调试工具

### 5.1 作弊面板：`DebugCheatsManager`

文件：`Gameplay/DebugCheats/DebugCheatsManager.cs`

按 `/`（或移动端四指触摸）打开，所有作弊都是 **Client → Server RPC**：

```csharp
[Rpc(SendTo.Server, RequireOwnership = false)]
void ServerSpawnBossRpc(RpcParams p = default)
{
    var newEnemy = Instantiate(m_BossPrefab);
    newEnemy.SpawnWithOwnership(NetworkManager.Singleton.LocalClientId, true);
    PublishCheatUsedMessage(p.Receive.SenderClientId, "SpawnBoss");
}
```

提供的功能：刷小怪/Boss、秒杀目标、清场、无敌、回血、加速、瞬移模式、开关门、开关传送门、直接跳 PostGame。

**设计亮点**：
- 用 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 包裹，Release 构建里整个面板被剥离（`Awake` 里直接 `SetActive(false)`）；
- 作弊使用会通过 `CheatUsedMessage`（网络消息）广播给所有人——"谁开挂了"公开透明，方便测试时定位；
- 作弊**执行在服务端**，所以和正常游戏逻辑走同一条路径，不会出现"只有作弊时才有的 bug"。

### 5.2 网络监控：`NetworkOverlay.prefab`

`Unity Multiplayer Tools` 提供的运行时 overlay：
- RTT、丢包、带宽；
- 每个 `NetworkObject` 的 RPC/NetworkVariable 统计；
- 场景内对象数量。

挂在 Startup 场景，`F10` 之类的快捷键切换显示。

### 5.3 弱网模拟

`NetworkSimulator`（Multiplayer Tools）可以配置：
- 延迟（固定/随机）；
- 丢包率；
- 抖动。

用来验证：
- 客户端预测（`AnticipateAction`）在 150ms 下的表现；
- `ClientReconnectingState` 是否能正确触发；
- `NetworkTransform` 插值是否平滑。

### 5.4 日志

`ConnectionManager.ChangeState` 每次都打一行：

```csharp
Debug.Log($"{name}: Changed connection state from {m_CurrentState.GetType().Name} to {nextState.GetType().Name}.");
```

联调时先看这行日志，能立刻知道卡在哪个状态。

## 6. 自动化测试

位置：`Assets/Tests/Runtime/`

| 测试 | 覆盖内容 |
| --- | --- |
| `ConnectionManagementTests` | 状态机跳转、审批拒绝、重连 |

| `MessageChannelTest` | 消息总线的订阅/退订/发布 |
| `NetworkedMessageChannelTests` | 网络消息的序列化与广播 |

## 7. 构建与多人联调

1. **Build Settings**：`Startup, MainMenu, CharSelect, BossRoom, PostGame`，`Startup` 在索引 0。
2. **Player Settings**：Company/Product Name 随意；`Api Compatibility Level = .NET Standard 2.1`。
3. **同一台机器跑两个客户端**：
   - 编辑器 Play（自动跳 Startup）；
   - 运行打包版，参数 `-AuthProfile player2`；
   - 或者两个打包版，分别 `-AuthProfile p1` / `-AuthProfile p2`。
4. **UGS 配置**：`Project Settings > Services` 绑定项目；`Edit > Project Settings > Boss Room`（如果有）填 `Application.cloudProjectId`。
   没有 UGS 也能玩：IP 直连模式。

> **编辑器多开**：v2.5.0 没有集成 Multiplayer Play Mode（v3 才加入该工作流）。可以用 ParrelSync（本项目已移除该依赖），或直接复制工程目录 / 用打包版联调。

## 8. 扩展指南

### 8.1 加一个新技能

见 [05](05-动作系统.md) 第 8 节。核心文件：
1. `Action/ConcreteActions/MyAction.cs`（+ `.Client.cs`）
2. `ScriptableObjects/Actions/MyAction.asset`
3. `GameDataSource.prefab` 的 `m_ActionPrototypes`
4. `CharacterClass` 的技能槽

### 8.2 加一个新角色

1. 新建 `CharacterClass`（ScriptableObject）：HP、速度、技能、Avatar 列表；
2. 新建 `Avatar` + prefab（模型、Animator、`ClientCharacter`、`ServerCharacter`、`PhysicsWrapper`、`NetworkObject`）；
3. 把 Avatar 注册到 `AvatarRegistry`；
4. 在 `NetworkCharSelection.AvatarConfiguration` 里加座位配置（CharSelect 的 8 个位置）；
5. 把角色 prefab 加进 `NetworkManager` 的 Network Prefabs 列表。

### 8.3 加一个新游戏状态（场景）

1. 新场景 + 一个 `GameStateBehaviour` 子类（同时是 `LifetimeScope`）；
2. 在 `GameState` 枚举加值；
3. 用 `SceneLoaderWrapper.LoadScene("MyScene", useNetworkSceneManager: true)` 切换；
4. 如果是服务端专属逻辑，记得 `if (!IsServer) enabled = false;`。

### 8.4 换一种连接方式（比如 Steam）

1. 实现 `ConnectionMethodBase` 子类，重写三个 `Setup*Async`；
2. 在 `OfflineState.Enter` 里根据条件创建它；
3. 传输层换成对应 transport，其余状态机不用动。

### 8.5 加一个"全局"系统

参考 [01](01-启动与依赖注入.md)：
1. 普通 C# 类 → 注册到 `ApplicationController.Configure`；
2. 需要 Update → 用 `UpdateRunner`；
3. 需要通知 UI → 定义消息 struct + 注册 `MessageChannel<T>`；
4. 需要服务端广播 → 用 `NetworkedMessageChannel<T>`（注意 `unmanaged` 约束）。

## 9. 常见坑

| 坑 | 说明 |
| --- | --- |
| 在 UI 的 `Awake` 里用 `[Inject]` 的字段 | 注入发生在 `Awake` 之后、`Start` 之前；`Awake` 里字段还是 null |
| 场景切换后 UI 引用失效 | UI 若挂在常驻场景（Startup/MainMenu）要 `DontDestroyOnLoad`，否则随场景销毁 |
| 直接 `FindObjectOfType<NetworkManager>` | 用 `[Inject] NetworkManager`，否则场景切换/对象池场景下会找错 |
| 弹窗关闭后没退订 | 用 `DisposableGroup`，别手动 `-=`（容易漏） |
| 作弊面板出现在 Release | 检查 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 是否包住了字段和逻辑 |
