## 3. 术语表

### Netcode

| 术语 | 含义 |
| --- | --- |
| **NetworkObject** | 可被网络生成/同步的对象，必须有唯一 `NetworkObjectId` |
| **NetworkBehaviour** | 继承自 `MonoBehaviour`，拥有 `OnNetworkSpawn/Despawn`、`IsServer/IsClient/IsOwner` |
| **NetworkVariable\<T\>** | 服务端权威、自动同步的状态值；新客户端加入时自动收到当前值 |
| **NetworkList\<T\>** | 可增量同步的列表（仅服务端可写） |
| **RPC** | 远程过程调用，用 `[Rpc(SendTo.X)]` 标注 |
| **`SendTo.Server`** | 客户端 → 服务端 |
| **`SendTo.ClientsAndHost`** | 服务端 → 所有客户端 + host 自己 |
| **`SendTo.SpecifiedInParams`** | 服务端 → 指定客户端（用 `RpcParams`） |
| **Named Message** | 不依赖 NetworkObject 的自定义消息（`CustomMessagingManager`） |
| **Connection Approval** | 服务端在客户端连接时决定"接受/拒绝"的回调 |
| **NetworkSceneManager** | 服务端发起、客户端跟随的场景加载 |
| **`OnSynchronizeComplete`** | 客户端完成场景同步（可以安全生成对象） |
| **PrefabHandler** | 接管 Netcode 的实例化/销毁（对象池） |
| **Ownership** | 对象的"所有者"客户端，影响 RPC 权限 |
| **Tick Rate** | 网络更新频率（Netcode 默认 30Hz） |
| **`INetworkSerializable`** | 自定义序列化接口 |
| **`INetworkSerializeByMemcpy`** | 可直接内存拷贝的 unmanaged 结构（最高效，但有约束） |
| **FixedString** | 定长字符串，避免托管分配 |

### 本项目 / 架构

| 术语 | 含义 |
| --- | --- |
| **LifetimeScope** | VContainer 的作用域，场景卸载时自动 Dispose |
| **EntryPoint (`IStartable`)** | 容器构建完成后调用 `Start()` 的服务 |
| **`[Inject]`** | 标记注入点（方法/字段/属性） |
| **Mediator** | 协调多个 UI 子面板的中间层 |
| **GameStateBehaviour** | 一个场景对应一个游戏状态，同时是 DI 作用域 |
| **Action** | 技能/动作的 ScriptableObject 逻辑单元 |
| **ActionPlayer** | 管理动作队列的运行时对象（服务端/客户端各一个） |
| **Synthesized Action** | 系统自动插入的动作（Chase/Target） |
| **PersistentPlayer** | 跨场景的玩家对象（名字、Avatar） |
| **Avatar** | 玩家在场景中的战斗实体 |
| **PhysicsWrapper** | 移动根 + 碰撞体，与模型分离 |
| **SessionManager** | 以 playerId 为键的会话数据（支持重连） |
| **ConnectStatus** | 连接结果枚举 |
| **ConnectionPayload** | 连接时携带的 JSON（playerId/playerName/isDebug） |

### 云服务

| 术语 | 含义 |
| --- | --- |
| **UGS** | Unity Gaming Services（Auth/Lobby/Relay 等的统称） |
| **Authentication** | 匿名登录，提供 `PlayerId` |
| **Lobby** | 房间服务：列表、玩家、自定义数据、事件推送 |

## 4. 常见问题（FAQ）

**Q：为什么 `OfflineState.cs` 的命名空间是 `UUnity.BossRoom...`（两个 U）？**
A：这是官方仓库里真实存在的拼写错误；`ConnectionManager.cs` 里用 `using UUnity.BossRoom.ConnectionManagement;` 兼容。**不要"顺手修好"**，除非你同时改所有引用。

**Q：为什么 Host 也是 Client？**
A：Netcode 的 Host 模式 = 服务端 + 本地客户端。所以 `ConnectionApproval` 对 host 也生效，`ClientPlayActionRpc` 的 `ClientsAndHost` 也包含 host。

**Q：客户端能直接改 `NetworkVariable` 吗？**
A：默认不能（`WritePerm = Server`）。只有标记 `WritePermission.Owner` 的变量 owner 能写。

**Q：为什么玩家角色不在连接时生成？**
A：需要等场景加载完（出生点、NavMesh 就绪），见 [04](04-场景与游戏状态.md) 4.1。

**Q：断线重连后为什么能回到原位置？**
A：`SessionManager<SessionPlayerData>` 保存了位置/HP/Avatar，`ServerBossRoomState.SpawnPlayer(lateJoin: true)` 会读取。

**Q：为什么 `MeleeAction` 要检测两次目标？**
A：网络延迟下"公平性"与"表现一致性"的权衡，见 [05](05-动作系统.md) 7.3。

**Q：`ActionID` 会变吗？**
A：每次启动按 `GameDataSource` 的列表顺序重新分配，**不持久化**。联机双方必须是同一构建/同一配置。

**Q：能不用 UGS 吗？**
A：可以。IP 直连模式不需要 Auth/Lobby/Relay，`GetPlayerId` 会退化为本地 GUID。

**Q：为什么 UI 不直接调用 `NetworkManager.StartHost()`？**
A：所有网络动作都经过 `ConnectionManager` 状态机，保证状态一致（比如不会在 `Hosting` 状态又调 `StartHost`）。
